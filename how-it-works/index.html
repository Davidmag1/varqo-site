How Varqo works

Turn autonomous execution into a verified control loop.

Varqo is designed to understand what a workflow depends on, verify the required facts and states independently, control continuation from evidence, recover safely when reality diverges, and preserve why each decision was made.

Product north star

KNOW → VERIFY → CONTROL → RECOVER → PROVE

Authorization is necessary, but it does not prove that the assumptions behind an autonomous action are true. Varqo adds an integrity loop around consequential execution.

The loop is intentionally state- and dependency-driven. It should increasingly reason about what must be true for the next step rather than relying on hardcoded function names.

Honest status: VERIFY is the current live-proven technical kernel. CONTROL and PROVE are partially implemented. Broader KNOW and generic automated RECOVER remain product direction.

Inside VERIFY + CONTROL

Prepare proof early. Bind runtime identity late. Trust neither the agent nor a success label.

For the current post-action wedge, Varqo prepares the proof requirement before a consequential write whenever possible. After the write, it binds only provider-returned runtime identity, executes an independent verifier, and evaluates authoritative observations against the required outcome.

Semantic preparation can be precompiled and persisted outside the live path. A runtime miss does not silently fall back to an LLM; it fails closed.

Recovery · product direction

When reality diverges, stopping is only the first safe move.

The purpose of recovery is to restore a state that can be independently proven safe, so the workflow can resume without turning every mismatch into permanent human babysitting.

Current status: generic automated recovery is not yet live-proven. The design principle is already fixed: every recovery action is a new consequential action and must itself be requirement-bound and verified.

Safe retry

Retry only when the operation is known to be safe or idempotent and duplication risk is controlled.

Re-read & reconcile

Observe authoritative state again and reconcile when the system may still be converging or reality changed outside the agent.

Compensate or roll back

Execute a known corrective action when returning to a safe state requires explicit compensation or rollback.

Human escalation

If Varqo cannot prove automatic recovery is safe, keep dependent execution held and require a human decision instead of guessing.

Safety principles

Ambiguity never becomes permission.

The control boundary is designed around independent evidence, explicit dependencies, and fail-closed behavior rather than model confidence.

Independent observation

Varqo queries authoritative state rather than treating the agent's own claim or provider dispatch response as sufficient proof.

Requirement-bound verdicts

Evidence counts only when it proves the specific condition the downstream workflow actually depends on.

Fail closed

Missing plans, verifier failures, malformed evidence, unknown states, wrong dependencies, and exhausted polling remain held or blocked.

Default-deny evidence

Audit artifacts preserve proof-bound evidence while excluding raw free-form tasks, provider bodies, and credential-like runtime data by default.
