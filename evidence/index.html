What is proven — and what isn't yet.

Varqo has moved from a state-divergence concept into provider-backed verification, a controlled agent continuation gate, composite outcome proof, hardened evidence persistence, deterministic failure-path testing, and restart-safe plan activation. The current evidence supports the VERIFY kernel and a narrow CONTROL boundary; it does not claim production readiness or generic recovery.

Live provider + agent proofs

Different protocols. The same integrity invariant.

The implementations differ, but continuation is never justified by a success label alone. It depends on independently observed state and an explicit requirement.

Dependent execution held

A real OpenAI tool agent requested completion before proof was ready. Varqo kept the dependent call held for about 9.78 seconds, then recorded one durable `HOLDING → RELEASED` transition after `VERIFIED`.

Evidence scope: controlled technical proofs of the integrity kernel and a narrow local control boundary. Not evidence of broad enterprise deployment, generic interception, distributed exactly-once execution, or generic recovery.

What changed after the first live demos

The POC is now testing integrity boundaries, not just happy paths.

Recent work focuses on whether the same release rule survives persistence, replay, ambiguity, failure, hostile claims, and process boundaries.

Composite controlled outcome · v1.0.13

A live agent's completion call stayed held until two independent layers passed: the provider action reached `completed` and a separate resource read converged from `off` to `active`. The earlier divergent run correctly remained held.

Default-deny evidence · v1.0.14

Audit persistence now projects typed proof evidence before redaction, omits raw free-form task/provider bodies by default, and pseudonymizes operational identities instead of treating a blacklist as the primary privacy boundary.

9/9 agent-integrity scenarios · v1.0.15

A deterministic local lab passed nine safety expectations spanning impatience, false success, forged identity, wrong dependency, replay, verifier outage, state divergence, and timeout. Only independently verified paths executed the idempotent dependent effect.

Restart-safe activation · v1.0.16

A separate runtime process loaded an already persisted plan with zero semantic calls and executed successfully. Starting with a missing required plan failed closed before provider mutation. Recovery of a proof interrupted mid-poll remains future work.

What the evidence establishes

The current technical wedge is increasingly automatic, reusable, and fail-closed.

Varqo's strongest claim today is not that every agent workflow is solved. It is that the verification/control kernel is surviving materially different provider topologies and increasingly adversarial execution conditions.

Automatic proof planning

Task/policy intent, provider schema, operation shape, and runtime context can compile into executable verification plans without a caller hand-authoring the full proof profile.

Runtime identity binding

Plans can be prepared and persisted ahead of execution, then safely rebound to provider-returned action or resource identities at runtime.

Evidence-based continuation

`VERIFIED` may release. Explicit failure may block. Missing, malformed, ambiguous, timed-out, or unavailable proof remains held rather than being promoted to permission.

Safe operational evidence

The proof chain preserves the conditions, authoritative observations, verdict, and gate result needed to explain a decision while minimizing sensitive runtime data.

Still hypotheses

The website should be as clear about the open questions as the repo is.

Varqo still needs to prove enterprise demand, broad cross-system generalization, acceptable production latency/cost, production interception, distributed continuation, safe generic recovery, and the larger KNOW surfaces around claims, memory, and multi-agent handoffs.
