Pending-proof recovery · local lab

A restart should not
mean a repeated write.

After trusted response capture, the local lab preserves pending work and its held dependency. A new process can resume the proof with the same state directory.

01 / CAPTURE

One provider write.

Capture the action result and persist the pending verification work. Keep the dependent effect held.

02 / RESTART

Resume explicitly.

A new process leases the captured work and revalidates the saved plan. It does not repeat the original write.

03 / VERIFY

Require real proof.

Independently verify action and resource state. Authenticate the local evaluator receipt before commit and release.

04 / RELEASE

One local effect.

Release only with valid proof. Replayed requests remain idempotent in the tested local path.

This proves a scoped local recovery path after capture. Atomic write-and-capture, production key isolation, tenant isolation, external effects, and generic rollback remain open work.
